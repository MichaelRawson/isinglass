# Directions

Consult @DESIGN.md for most design decisions.
Aim for a concise implementation, using simple Prolog.
Split complex procedures into multiple sub-procedures where it aids readability.
Use descriptive names for predicates and try to keep to a reasonable number of arguments.

You might like to 'mutate' proofs as a way to test new features against the checker.
When testing, be careful running with long timeouts as you may exhaust memory.
Do _not_ try to investigate why backends like lambdapi are slow on a given input. It's not our problem.
